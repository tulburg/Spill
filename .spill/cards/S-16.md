## Purpose
Every change to the board, from Claude or from the user, goes through Spill instead of hand-edited files. Claude uses the `spill` MCP server; the user uses the `spill` command until the canvas app exists.

## Requirements
1. `spill mcp` runs an MCP server over stdio exposing the 10 tools in SPILL.md section 2. It finds `.spill/` by searching up from the working directory.
2. Cards stay one markdown file each in `.spill/cards/`, in the current format. Existing cards load and save without losing content.
3. IDs take the next free number per kind and are never reused, even after a card file is removed (highest number per kind is kept in `.spill/state.json`).
4. Status rules: `spill_set_status` refuses `approved` and `rejected`, accepts only statuses valid for the card kind, and enforces `maxActiveSpecs` from config.
5. User commands: `spill board`, `spill show ID`, `spill approve S-n [note]`, `spill reject S-n reason`, `spill answer Q-n text` (records a D-n and closes the question), `spill comment ID text`, `spill ask title [body]`. Only these set `approved` or `rejected`.
6. Every change appends one line to `.spill/events.jsonl`: time, actor (user or claude), action, card, detail.
7. `spill_inbox` returns user events since Claude's last inbox call, then moves the cursor.
8. No runtime dependencies. Runs on bun.

## Out of scope
- The canvas app (S-1 to S-15 describe it).
- Noticing hand edits to card files.

## Acceptance checks
- `bun test` passes.
- With `.mcp.json` in this repo, Claude Code lists the 10 spill tools.
- `spill approve S-16` by the user shows up in the next `spill_inbox` call.
