## Purpose
Part 1 of S-42. Give each spec a place for its designs and give Claude MCP tools to draw them, ported from OpenDraw's MCP tools so we do not start from zero.

## Requirements
1. Designs live in .spill/designs/S-n/, one HTML file per artboard with inline CSS, plus a small index (artboard id, title, variant, size, created, status).
2. Artboards are grouped into variants (A, B, C) so a spec can offer several directions.
3. New MCP tools, named and shaped after OpenDraw's (shared/mcp in OpenDraw, its own MIT code): spill_design_create_artboard, spill_design_write_html (insert or replace children of a node), spill_design_read (HTML of an artboard or node), spill_design_update_styles, spill_design_duplicate, spill_design_delete, spill_design_list.
4. spill_design_screenshot renders an artboard to PNG so Claude can check its work (headless WebKit in the Mac app, or the board server).
5. Nodes have stable ids so Claude can edit part of an artboard without rewriting it.
6. Every design change is an event on the board (actor claude, card S-n), so the app updates live.
7. No new dependency without asking: OpenDraw's tools use zod for argument shapes; Spill's tools use plain JSON schema today, so the port uses JSON schema unless you approve zod.

## Out of scope
- Showing designs in the app (S-45), review (S-46), versions (S-47).

## Acceptance checks
1. Through MCP, Claude creates two variants with one artboard each for a spec; files and index appear under .spill/designs/S-n/.
2. write_html into a node and read it back returns the same HTML; update_styles changes only that node.
3. spill_design_screenshot returns a PNG that matches the HTML.
4. Unit tests cover create, write, read, update, duplicate, delete and list.
