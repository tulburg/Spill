## Purpose
While Claude builds a spec, its card shows a single progress bar for requirements met. Requirements are checked off late, often all at once, so the bar sits at 0 for most of a build. Claude's own todo list for the build fills steadily, so showing it next to the requirements shows real progress.

## Requirements
1. When Claude starts building a spec (it becomes active, for a first build or an update build), it records a todo list for that build through MCP and ticks items off as it works. The tool takes the full list each time (each item's text and whether it is done), so Claude can add, reword or tick items.
2. Starting a build clears the previous build's todo list, so the todo side begins at 0. Requirements met in earlier builds stay counted, as today.
3. The building card's progress bar becomes two bars on one line, 4px apart. The left bar takes 75% of the width and shows todos done out of the total. The right bar takes 25% and shows requirements met, exactly as the single bar does now.
4. The label row reads, for example, "3 of 8 todos" on the left and "2 of 6 reqs" on the right, each lined up with its bar.
5. Before Claude records a todo list, the left bar is empty and its label reads "No todo list yet".
6. Todos are not shown anywhere else: not in the spec text, the side sheet, Activity or the File tab. Recording or ticking one does not add an activity line or change the card's "latest action" line. They are kept in .spill so the bar survives a reload.
7. The MCP instructions (the server's instructions, the tool's description and SPILL.md) tell Claude to record the todo list right after setting a spec active, before writing code, and to tick each item as it finishes.

## Out of scope
- Showing or editing todos in the UI.
- Changing how requirements are checked off ("Reqs 1-n done").
- Progress on cards that are not being built.

## Acceptance checks
1. Setting a spec active and recording 4 todos with 1 done shows the left bar at 25% labeled "1 of 4 todos", next to the requirements bar.
2. The two bars sit on one line 4px apart, at 75% and 25% of the width.
3. Ticking more todos fills the left bar live, without a reload and without new Activity lines.
4. An update build on a done spec starts the todo side at 0 and keeps the requirements met before.
5. With no todo list recorded, the left side reads "No todo list yet".
