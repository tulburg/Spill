## Purpose
Spill is light only. A dark theme needs every color in the app to come from tokens, with a dark value for each.

## Requirements
1. Every color in ui/app.css and the inline SVGs and styles in ui/main.ts comes from a CSS custom property; no hard-coded hex colors remain outside the token definitions (the logo and the macOS traffic lights excepted).
2. Tokens are defined twice: light values (today's colors, unchanged) on :root, dark values on :root[data-theme="dark"].
3. Dark values use near-black surfaces (canvas, cards, sheet, panels, inputs), lighter text, and status colors (amber, green, teal, indigo, red) tuned to stay readable on dark: card tints become low-opacity fills, borders become subtle.
4. Everything that signals status keeps its meaning in dark: building shimmer and spinner, held amber, quiet dashed, approved seal, done check, rejected and replaced dimming, update requested, diff added and removed lines, connector lines and the spotlight ring.
5. The theme is set by data-theme on the html element: "light", "dark", or removed for system, which follows prefers-color-scheme. Switching it changes the page without a reload or a flash.

## Out of scope
- The setting that chooses the theme (S-39).
- Custom accent colors, more themes.
- The landing page (S-37).

## Acceptance checks
1. A search of ui/ for hex colors finds them only in the token definitions (plus the listed exceptions).
2. In light mode the board looks the same as before (screenshots compared).
3. In dark mode the canvas, a spec in each status, open and answered questions, a decision, the sheet, the summary panel and the message thread are all readable, with every status distinguishable.
4. Setting data-theme to dark, light, or removing it switches the theme live; with it removed, it follows the OS setting.
