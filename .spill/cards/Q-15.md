S-32 lets you ask for a change on a built spec instead of reverting it. Today a done spec can only become active again by being reverted, re-approved and queued. My pick is C: small fixes stay quick, and larger changes still get a spec you approve.
- A. Same spec: it goes straight back to active (no re-approval), Claude makes the change, re-runs the checks and sets it done again.
- B. Follow-up spec: Claude drafts a small new spec linked to the done one, for you to approve and build.
- C. Claude decides: small adjustments as in A, anything that adds a requirement as in B, saying which in a reply.
