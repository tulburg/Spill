## Purpose
When a spec is updated after a change request, you should see what changed instead of rereading the whole spec (D-17). The diff marks only what really changed: a small edit to a line shows inline in that line, not as the whole line removed and added again.

## Requirements
1. Whenever a spec's text changes, the store keeps the previous text as a version, with when it changed and who changed it.
2. The version a spec had when it was last approved is marked as the approved version.
3. A spec waiting for approval again after an update shows "Changed since approved" in the sheet header, and the Overview shows the diff against the approved version by default, with unchanged sections collapsed.
4. The sheet lists the versions (time and who), and picking one shows its diff against the current text.
5. spill_get on a spec with an approved version includes a short summary of the changes since it, so Claude can explain them.
6. The design is drawn in Paper (file "Spill", page "Work board v2") and approved on the board before it is built.
7. The diff is inline. A changed line that is still mostly the same line (about half its words or more kept) shows once, as unchanged text with only the removed words struck through in red and the added words in green.
8. Only lines with no counterpart are marked as wholly added (green, "+") or wholly removed (red, struck through, "-").
9. Renumbering is not a change: a numbered item whose number changed but whose text did not shows as unchanged, with its new number.
10. spill_get's summary uses the same pairing: a changed line reads "~ new text" instead of a "-" and "+" pair.

## Out of scope
- Versions for questions and decisions.
- Restoring an old version from the sheet.
- Character-level diffs inside a word.

## Acceptance checks
1. Updating a spec's text twice leaves two versions with times and authors.
2. A re-updated spec waiting for approval shows "Changed since approved" and a diff.
3. Picking an older version shows its diff against the current text.
4. spill_get lists the changes since the approved version.
5. Inserting a requirement as item 2 shows only the new item 2 as added; the old 2 to 8, now 3 to 9, show as unchanged.
6. Changing one word in a line shows that line once, with the old word struck through and the new word marked.
7. A line rewritten completely shows as one removed and one added line.
