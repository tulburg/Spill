## Purpose
A built spec usually gets updated, not rejected. Asking Claude to update it is the main action on a done spec, and Claude handles it on the same spec where it can (D-17).

## Requirements
1. On a done spec, the sheet footer is a multiline box "How should S-n be updated?" with an "Update" button styled as the primary action (D-21). Enter sends, Shift+Enter breaks the line.
2. Revert is removed from done specs (D-16). Approved, queued and active specs keep it.
3. Sending stores an update request on the spec. spill_inbox lists it as action "update" with the text, separate from plain comments. While it is open, the box below it adds to the same update.
4. The card on the canvas and the sheet header show "Update requested" in place of "Done" until Claude acts on it: moves the spec, comments or replies on it, or asks a question that blocks it. The sheet shows the text at the top as "Your update, Waiting on Claude".
5. While an update request is open, Claude may move the done spec straight to active (no re-approval) when the update fits the spec as written, or update the spec text and move it to draft, where it waits for approval again. Without an open update request, a done spec still cannot be reopened by Claude.
6. Claude may ask questions on the spec (blocking it) before deciding.
7. SPILL.md, the MCP instructions and the tool descriptions say how Claude handles an update request (D-17): same spec when it fits; spec text updated and re-approved when it must change; a replacement (S-35) only when the update is too big.
8. The design is drawn in Paper (file "Spill", page "Work board v2") and approved on the board before it is built.

## Out of scope
- Versions and the diff view (S-34).
- Branching or replacing a spec (S-35).

## Acceptance checks
1. A done spec's sheet shows the multiline box with "Update" as the primary action and no Revert button.
2. Sending an update shows in spill_inbox as action "update" with its text.
3. The card shows "Update requested" until Claude moves, comments on, or blocks the spec.
4. With an update request open, Claude can set the done spec active; without one, setting it active is refused.
5. Claude can update the spec and set it to draft, and it then needs approval again.
