## Purpose
A spec that was approved can be taken back down, and the board shows that it was once approved and why it was pulled.

## Requirements
1. The user can revert an `approved`, `active` or `done` spec, with an optional reason. Only the user can revert, like approve and reject.
2. Reverting moves the spec back to `discussing` (D-7). There is no new status.
3. A reverted card shows a "Reverted" note with the reason and when, until it is approved again.
4. If the spec was `active`, Claude is told through `spill_inbox` and must stop work on it.
5. The card history keeps the approval and the revert (who, when, reason).
6. A reverted spec can be edited and approved again; the note then goes away.

## Out of scope
- Automatically reverting code that implemented the spec.
- Claude proposing a revert (it can comment instead).

## Acceptance checks
- Revert an active spec: it moves to discussing, the building state stops, `spill_inbox` reports the revert, the card shows the note and reason.
- Approve it again: the note goes away.
