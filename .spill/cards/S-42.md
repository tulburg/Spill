## Purpose
Designs for a spec live in Paper or OpenDraw today, outside the spec. The spec should own its designs: Claude drafts them through Spill's MCP server, the spec's viewer shows the renders, and you review them there, with annotations, comments and accept or reject per variant. Every spec version keeps the designs it had.

## Requirements
1. Designs are stored with the spec in .spill (one folder per spec), as HTML artboards with inline CSS, so they render without another app.
2. Spill's MCP server gains design tools modeled on OpenDraw's (shared/mcp in OpenDraw, its own MIT code): create artboard, write HTML into it, read HTML back, update styles, duplicate, delete, list, and a rendered screenshot so Claude can check its work.
3. The spec viewer gets a Designs tab: each artboard rendered in an isolated frame, zoomable, grouped by variant.
4. Review: you can pin annotations on a design, comment on it, and accept or reject each variant. Claude sees all of it in the inbox.
5. Accepted and rejected variants stay on the spec as history; nothing is deleted.
6. Each spec version records which designs it had, and viewing an older version shows those designs.
7. A spec with designs waiting for review cannot be approved until one variant is accepted (like open questions today).

## Out of scope
- Editing designs by hand in Spill (Claude edits them; you review).
- The iOS app's design viewer (part of the companion app spec).

## Acceptance checks
1. Claude creates two variants for a spec through MCP; both render in the spec's Designs tab.
2. An annotation and a comment on a variant reach Claude's inbox; accepting one and rejecting the other is shown on the spec.
3. After a spec update, the older version still shows its own designs.
