## Purpose
Specs are updated as the work moves (S-33), so the same S-n can mean different text over time. Showing the spec's version on its card makes it clear which version is approved or built, and when a newer version is waiting for approval.

## Requirements
1. A spec's version counts approval rounds, not text edits. A new spec is v1. After it is approved, the first change to its text starts the next version (v2), and later edits before the next approval stay part of v2.
2. The spec card shows its version as a small "v2" in the top right corner, whether the spec is draft, approved, queued, building, done or rejected.
3. A spec whose current text is a newer version waiting for approval (changed since its last approval and not yet approved again) shows that newer number with a "new" mark, for example "v3 new", and a tooltip that names the version that was approved before it ("v2 approved 3d ago").
4. Once the user approves it, the mark goes and the card shows the plain number ("v3").
5. The side sheet's header shows the same version label next to the status.
6. The version list in the sheet's "Compared with" menu and the design snapshot labels (S-47) use the same numbers. Several text edits within one version show as edits of it (for example "v3, edit 2"), so the numbers match the card.
7. spill_get and spill_board show the version too (for example "S-46 v3"), so Claude refers to the same number the user sees.

## Out of scope
- Changing when versions are saved or how the diff works (S-34).
- Version labels on questions and decisions.

## Acceptance checks
1. A new spec shows "v1"; after approval and a text change it shows "v2 new"; after approval it shows "v2".
2. Several edits before the next approval keep "v2 new", and the compare list shows them as edits of v2.
3. The sheet header, spill_get and spill_board show the same version as the card.
4. A design snapshot taken at the v2 approval is labeled v2.

## Comments
- Claude (2026-11-13): Reqs 1-7 done.

Versions count approval rounds. A text edit starts the next version when the current one has been approved since it began. Two refinements came out of testing on the real board:
- Edits made while the spec is being built stay in the version being built. Recording a decision mid-build (S-47's D-35 edit) is not a new version.
- The "new" mark shows only while the spec is waiting for approval (draft or discussing).

The tag sits at the top right of the card and in the sheet header. The compare menu reads "v2, edit 1" when a version has several edits. Design snapshots carry their version, and spill_board and spill_get show the label. 64 tests pass.
