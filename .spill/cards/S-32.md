## Purpose
A built spec is rarely rejected; usually it gets adjusted. This is the overview of how a done spec changes after it ships (D-17): Claude handles a change on the same spec when it can, shows you what changed when the spec text is updated, and replaces the spec only when the change is too big.

## Parts
- S-33 Ask for a change on a done spec: "Ask for a change" replaces Revert in a done spec's sheet (D-16); the request reaches Claude, the card shows "Change requested", and Claude reopens, asks about, or updates the same spec.
- S-34 Spec versions and a diff view: every update keeps a version, and a spec waiting for approval again shows what changed since it was approved.
- S-35 Replace a spec when a change is too big: Claude branches a new spec, or proposes deleting the spec and its code and replacing it, with your confirmation.

## How they fit
S-33 comes first: it is the flow you use. S-34 makes S-33's "update and re-approve" path readable. S-35 is the path for changes too big for the same spec. This spec is done when all three are done.
