## Purpose
Some changes are too big for the same spec. Then Claude branches a new spec, or deletes the spec and replaces it with a new one, where deleting a spec means deleting all of its implementation and code (D-17).

## Requirements
1. Claude can branch: draft a new spec that follows a done spec, linked to it and shown next to it on the board.
2. Claude records the files it touches on a spec as it builds, and the spec shows them as a "Files" list (D-20).
3. Claude can propose deleting and replacing a done spec. The proposal is a question on the board that names the spec, the replacement spec and the files from its Files list that would be removed or changed.
4. Nothing is deleted until you confirm that question.
5. After you confirm, Claude removes the spec's implementation using its Files list and records what it removed on the spec.
6. The old card stays on the board as "Replaced": dimmed, linked to its replacement, with its questions and decisions kept (D-19).
7. SPILL.md, the MCP instructions and the tool descriptions say when to branch, when to propose a replacement, how to record files, and that deletion needs your confirmation.

## Out of scope
- Replacing specs that are not done.
- Undoing a deletion from the board (git history keeps the code).
- Backfilling Files lists for specs built before this one.

## Acceptance checks
1. A branched spec is linked to the done spec it follows and drawn next to it.
2. Files Claude records while building show in the spec's Files list.
3. A replacement proposal appears as a question naming the spec, its replacement and the files to remove.
4. Before confirmation no code is removed; after it, the removal is recorded on the spec, the card shows "Replaced" dimmed, and it links to its replacement with its questions and decisions kept.
